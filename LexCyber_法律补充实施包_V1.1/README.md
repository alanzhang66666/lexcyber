# LexCyber 法律补充实施包 V1.1

本压缩包汇总双方对 LexCyber 提出的法律规则、法源、文书、候选路径、页面措辞、迁移与会签补充需求，可用于开发分工、法学复核、测试与部署验收。

**核心性质**：这是“实施规范 + 人工复核草案 + 验收材料”，**不是已经合并代码的补丁、完成会签的规则包或可直接在生产环境播种的配置**。其中 `*.review.json` 是供法学与工程共同审定的结构化草案，严禁直接注册为 `approved`。

## 内容索引

- `00_总览/`：当前主分支核对、开发优先级与范围边界。
- `01_法源/`：2016/2025 网络安全法分版登记草案、旧新法时效与条号衔接。
- `02_规则/`：帮信构成要件、八条严重情节、掩隐与诈骗共犯界分、candidate_paths 声明及额外严重情节的人工核查。
- `03_文书/`：四种模板的字段与条件约束、样稿结构、案型映射、文书渲染设计。
- `04_页面/`：量刑、检索、合规、定罪的文案替换及显示边界。
- `05_迁移与生效/`：金额类型、V27 核查、播种、签署、版本退役、501 门闩流程。
- `06_验收/`：覆盖所有关键边界条件的测试矩阵和发版清单。
- `MANIFEST.json`：文件 SHA-256 清单。

## 使用顺序

1. 法学负责人审核法律依据和事实口径，尤其是八条路径非穷尽、客观证据推认明知、旧新网络安全法及文书正式格式。
2. 工程核对环境是否存在 app V27、1.1.0 规则，并建立需要的新版本；严禁修改已批准注册表记录、已应用迁移和冻结比赛包。
3. 分别实现法源数据、规则与数据结构、模板引擎、页面措辞、测试。
4. 先在隔离/测试环境运行迁移、播种及验收，完成法学负责人 `signoff()` 及版本 `superseded` 关系验证。
5. `/v1` 检索、量刑、合规、定罪维持 501，**会签完成 ≠ 公开口解禁**。公开解禁须另行授权与验证。

## 基于仓库的核对范围

2026-10-10 核对可访问的 GitHub `alanzhang66666/lexcyber` main：`core_rules.json` 仍为 1.0.x、`core_templates.json` 只有通用模板且 required 仅姓名、`document_render.py` 为占位符替换+阻断；`conviction_paths.py` 已具备显式 `candidate_paths` 执行机制，但当前规则未声明实际法律路径。本包不推定你所在部署环境/未推送分支中 1.1.0 或 V27 的实际状态；以 Flyway、规则注册表和内容哈希为准。
