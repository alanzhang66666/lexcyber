# 文书体系与服务端渲染改造

当前 `core_templates.json` 只有 `indictment-assist@1.0.1`，其中 `field_schema.required` 仅姓名；`document_render.py` 只支持 `{{path}}` 占位符并在缺失时 blocked。请勿直接把本包的 schema 设计草案播入现有引擎。

## 四份模板

1. `indictment-draft` 支付结算型起诉书：**恢复已签 1.0.2 原文**，核对数据库内容 hash；新内容升新版本。支付结算必须来自 `amounts.payment_settlement_amount.confirmedSum`；身份、诉讼权利告知、退补/延长期限、证据分类、附件、署名及法律依据须核查。
2. `indictment-assist` 通用型起诉书：不强制支付结算金额；覆盖身份、程序审查、上游事实、帮助行为、明知、情节严重、证据分类、法律依据和签署。
3. `non-prosecution-decision` 不起诉决定书：法定、酌定、证据不足、未成年人附条件互斥；附条件须独立校验刑诉法第282条等要求。申诉/复议复核/其他救济的文案按类型、权利主体分别生成。
4. `sentencing-recommendation` 量刑建议书：通常主刑必填；免刑不填写主刑、执行方式、附加刑；9.0/8.1月只作计算参考，不自动写入正式建议。

## `document_render.py` 需要新增的能力

- `applicability`：文书与程序状态、帮助类型和人工选择关联；界分未定时不得自动选起诉书。
- `conditional_required`：按模板类型、年龄、免刑、程序状态校验必填。
- `mutually_exclusive`：互斥值/互斥段落；不起诉类型或免刑与普通主刑的矛盾必须 blocked。
- `conditional_sections`：按法学批准的规则选择正确正文段落，不能只做字符串替换。
- 权利告知按类型/权利主体的版本受控正文，不允许自由模型编造。
- 所有模板必须有正式文书样式法学审定；程序事实是必核数据，不代表全部必须出现在最终正文。
- `unresolved` 应明确指出缺失路径、缺失条件、互斥冲突、法源缺口和上游工件阻断。
- 字段无法通过服务端核验时，输出 `status=blocked` 且不产完整正文。最终仍保留 `human_review_required`。

## 案型映射

| 案件程序/业务状态 | 模板 | 备注 |
|---|---|---|
| 经人工确认提起公诉且为支付结算型帮信 | indictment-draft | 需要专属金额口径 |
| 经人工确认提起公诉的帮信通用型 | indictment-assist | 不强制支付结算金额 |
| 经人工确认作不起诉处理 | non-prosecution-decision | 四类条件互斥 |
| 经人工确认作量刑建议 | sentencing-recommendation | 与起诉书可关联，但需分别审查 |
| 帮信/掩隐/诈骗界分未定 | 无自动文书 | 只显示候选和待核查事实 |

**核心原则**：草稿模板不能代替检察官起诉/不起诉决定，亦不能自动落章、签署。起诉书与不起诉决定书、起诉意见书是不同业务文书，不得仅因旧语料的正文标题而混用。
