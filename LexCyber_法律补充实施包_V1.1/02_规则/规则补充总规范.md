# 帮信、严重情节及近邻罪名界分补充规则

## 1. 构成要件 `rule-conviction-assist-287-2-elements`

四项必要条件：上游存在利用信息网络实施犯罪事实 AND 实际知道 AND 有三大类帮助行为 AND 情节严重。

- `knowledge_of_crime` 的终态满足值仅 `explicit`（实际知道），取消 `presumed` 作为直接满足值；历史 `presumed` 进入待审，不直接批量转 explicit。客观事实可以支持证明“知道”，但须展示推断依据和相反证据。
- 一级帮助行为仅 `technical_support`、`payment_settlement`、`advertising_promotion`；技术支持再分互联网接入、服务器托管、网络存储、通讯传输。
- 严重情节采用独立规则结果汇总为第四必要条件，不将任何单个阈值等同于帮信全部要件。
- 全部要件、证据、法源满足且无已核实排除时，可展示“建议罪名（供人工复核）”；否则说明待核查/已证实排除理由，掩隐及诈骗为独立候选路径。

## 2. 严重情节 `rule-conviction-assist-severity-2019-threshold`

**八条确定性路径择一满足**，但还应单列“造成严重后果”“其他严重情节”的人工核查；不得宣称八条穷尽法定情形。

| 路径 | 条件 | 口径/前置事实 |
|---|---|---|
| S1 | 帮助对象 >=3 | 无须额外同时达到30万；核对不同被帮助对象 |
| S2 | 支付结算金额 >=200000元 | `payment_settlement_amount` |
| S3 | 提供资金 >=50000元 | `provided_funds_amount`，核查以投放广告等方式提供资金的事实 |
| S4 | 违法所得 >=10000元 | `illegal_gain` |
| S5 | 2年内受有关行政处罚且又提供帮助 | 严格核对行政处罚类型、时间、决定文本和后续行为 |
| S6 | 出租出售本人账户 >=3 且流入 >=300000元 | `account_total_flow`、`self_account_count`，AND |
| S7 | 收购/出售/出租非本人账户且流入 >=300000元 | `account_total_flow`，无额外3账户要求 |
| S8 | 收购/出售/出租电话卡或物联网卡 >=20张 | 唯一编号去重；可作待实施人工核查，不得宣称已自动覆盖 |

八条路径内的金额不得跨口径替代。需保留 actorId、账户范围、交易期间、金额及 `component_of` 去重。2025年涉账户等规定应进一步核实对应上游犯罪和相关资金性质，不能只因总流入足额就确认刑责。

## 3. 掩隐界分 `rule-distinction-concealment-after-upstream`

- “上游已经既遂”本身既不能排除帮信，也不能推出掩隐。
- 确认**仅在上游既遂后首次介入**，且没有此前持续帮助时，才可审查相应帮信路径的时间排除事由。
- 掩隐为**候选罪名**，须独立核实资金为犯罪所得及其收益、转移掩饰方式、主观明知等。
- 有事前通谋，应提示核查上游犯罪共犯路径；持续性参与须按时间轴审查。

## 4. 诈骗共犯 `rule-distinction-fraud-accomplice-prior-collusion`

- F1：事前通谋 + 具体明知 + 支持或参与行为。
- F2：即使无事前通谋，若上游既遂前形成稳定配合，具有具体明知、较长期固定的关系及实质性参与，可提示诈骗共犯候选路径。
- 仅概括明知、偶发帮助、一次性账户出租、仅知可能涉及违法，不足以认定诈骗共犯要件满足；倾向继续沿帮信审查。
- 提示属于候选审查，不是共犯结论。

## 5. 合规与案例A

- 实名：有制度而确认未实际执行 -> `not_met`；未知 -> `unknown`；冲突 -> `conflicted`。制度文件不能代替执行记录。
- 日志：六个月规则不改，只补有效法律版本关联及实际留存证据审查。
- 案例A：现有9.0个月、坦白后8.1个月保持不变；案载12–18个月记为偏重建议。只修改非冻结说明，不改冻结比赛包。

## 6. 统一输出约束

建议罪名仅是候选路径优先级；只输出：建议罪名、候选罪名、要件命中、待核实事实、排除事由、支持/相反证据、风险提示。事实缺失不能写成罪名已排除。所有法律结论须人工复核。
