# 播种、法学会签、版本退役及公开门闩运行手册

## 一、变更核对

- 核对代码所在commit、V27、1.1.0是否在目标分支/环境中真实存在，勿仅依据文档文字。
- 从已签注册表核对 `indictment-draft@1.0.2` 原始模板与哈希，恢复语料；新法律内容建立后续版本。
- 新法源2016/2025文本均应初始 `pending`；规则、模板亦如此。不得假造完成审批。

## 二、依赖排序

1. 数据库前向迁移及金额类型验收（先让 `account_total_flow`、`provided_funds_amount` 成为合法kind）。
2. 录入两个版本的《网络安全法》及版本接续；复核官方来源、效力、条号、哈希。
3. 录入规则新版本，核对覆盖 `coverage.covers`、源引用、事实键、candidate_paths、金额字段。
4. 录入四种文书及条件引擎对应契约，核对正式格式及字段法律含义。
5. 由法学负责人经授权 `registry.signoff()` 审核；旧的 approved 行不可原地改写。
6. 验证有效只读视图只包含获批且法源闭包完整的新版本，退役旧版本标记superseded；历史保持可重放。
7. 基于固定事实快照完成执行、审核、发布、时点差异与stale传播回归。

## 三、501门闩

`/v1` 以下公开能力在单独验收授权前保持 `501`：法源检索、量刑计算、合规分析、定罪分析。

**必须区分**：已写规则 ≠ 已播种；已播种 ≠ 已会签；已会签 ≠ 公开解禁。`/v2` 继续走批准规则包/引擎适配器/能力门闩，不得绕过。

## 四、禁止事项

- 不将 review JSON 直接变成 `approved`。
- 不改已应用Flyway、不覆盖历史模板/法源/规则、不修改冻结比赛包。
- 不自动将计算参考值写成正式量刑建议；不自动选择起诉书。
- 不因资料缺失就写“已排除某罪”，不因上游既遂就“认定掩隐”。

## 五、留痕材料

保留迁移执行输出、内容SHA、签署人/权限、批准时间、规则法源模板版本、测试报告、公开口返回码与后续解禁审批凭证。
