# 法学会签清单

**现状日期：** 2026-09-19
**契约版本：** 0.8.0
**适用范围：** 检索、量刑、合规分析、定罪分析与文书字段字典的会签跟踪

> 本工作台辅助研判，不替代司法裁量；不产出量刑、责任或犯罪结论。

## 状态与执行约束

- **待签：** 尚未完成法学会签；对应公开接口或能力维持 `501`，不得以实现已完成或页面已接通作为解禁依据。
- **已签：** 会签完成但尚未执行解禁后验收；主表中的解禁归属轮次必须明确，不得填「未定」。
- **已解禁：** 会签完成且解禁后验收动作通过；状态变更必须同步记录验收产物和实际解禁轮次。
- 在五条条目均未签署期间，实现工作可以继续推进，用于准备契约、页面、测试、审计和验收材料；但必须保持默认开关关闭，并保持检索、量刑、`compliance.analyze`、`conviction.analyze` 四处公开能力的 `501` 返回码不变。
- 本清单记录的是待会签事项，不构成解禁授权。法学负责人、产品负责人和工程负责人应分别对会签内容、验收证据和开关状态负责。

## 条目明细

### SIGNOFF-001：检索公开口

<a id="signoff-001"></a>

**待会签内容：**

- 确认 `POST /v1/sources/search` 返回的法源检索内容、来源标识、时间信息和引用范围可以如何用于辅助研判。
- 确认来源不可用、检索失败、结果为空和内容不完整时的提示与审计边界。
- 确认检索结果不得被解释为自动作出的司法裁量、责任或犯罪结论。

**负责人：** 法学负责人、检索轨道负责人。

**安全门闩与默认开关：**

- Java 公开门闩位于 `SourceSearchController` 的 `POST /v1/sources/search`。
- Engine 侧对应 `engine/adapters/sources.py` 的 `SourceSearchUnavailable` 分支。
- 默认开关为 `LEGAL_SOURCE_SEARCH_ENABLED`，默认保持关闭。

**未签署期间：**

- `POST /v1/sources/search` 继续返回 `501`，不因前端入口、适配器或测试材料已准备而提前解禁。
- 实现工作可继续推进，但只能作为解禁前置工作；不得改动上述 `501` 门闩或默认开关取值。

**解禁后验收动作：**

1. 完成法学会签并留存签署记录。
2. 使用代表性查询验证来源可追溯、引用范围、失败分支和审计记录。
3. 在 Java 与 Engine 两侧核对开关和能力状态后，由授权负责人决定是否执行公开口解禁；验收未通过时继续维持 `501`。

**当前状态：** 待签；对应返回码 `501`；解禁归属轮次 R3。

### SIGNOFF-002：量刑公开口

<a id="signoff-002"></a>

**待会签内容：**

- 确认量刑任务的事实输入、规则依据、计算过程、结果展示和复核记录的法律语义与使用边界。
- 确认量刑结果仅用于辅助研判，不替代司法裁量，不产出量刑、责任或犯罪结论。
- 确认 Java 侧任务创建门闩与 Engine 侧执行开关必须保持一致，不能只验证任务能够创建。

**负责人：** 法学负责人、量刑轨道负责人。

**安全门闩与默认开关：**

- 公开任务入口为 `POST /v1/tasks`，任务类型为 `metadata.taskType=sentencing.calculate`。
- Java 侧由 `TaskPolicies.requireSupported` 的 `SENTENCING_UNAVAILABLE` 分支控制。
- 对应默认开关名称为 `SENTENCING_ENABLED`；Java 配置与 Engine 配置均默认关闭。

**已核实的单侧开启现状：**

- 只开启 Java 侧 `SENTENCING_ENABLED`（即 Java 的 `sentencing.enabled`）时，Java 可以放行任务创建，但这不代表 Engine 已具备执行条件。
- Engine 侧 `engine/settings.py` 的 `sentencing_enabled` 仍为 `false` 时，Engine 适配器会抛出 `SentencingUnavailable`。
- 该任务随后会被 Engine 标记为 `failed`，因此「只开 Java 开关」不是有效解禁路径，也不能作为发布或会签验收证据。
- 当前正确的安全状态仍是未会签期间公开量刑能力返回 `501`，并保持 Java 与 Engine 两侧默认开关关闭。

**未签署期间：**

- 量刑任务创建及其公开能力继续由安全门闩阻断并返回 `501`，不因 Java 单侧开关、页面已接通或适配器已存在而提前解禁。
- 实现工作可继续推进，但不得改变 `SENTENCING_ENABLED` 的默认值，不得以单侧开启绕过安全门闩。

**解禁后验收动作：**

1. 完成法学会签并留存签署记录，确认量刑事实、规则、计算结果和展示边界。
2. **同时开启 Java 与 Engine 两侧开关**：Java 侧 `SENTENCING_ENABLED` / `sentencing.enabled` 与 Engine 侧 `sentencing_enabled` 必须一致；不得只开启其中一侧。
3. 通过公开任务入口创建 `metadata.taskType=sentencing.calculate` 任务，验证任务实际进入 Engine 执行链路。
4. 核验任务不再被 Engine 标记为 `failed`，并核对结果、错误分支、审计记录和复核归档；若仍为 `failed` 或两侧开关不一致，验收失败并恢复公开口 `501`。
5. 只有在上述双侧一致性和法学验收均通过后，才可由授权负责人决定是否解除量刑公开口门闩。

**当前状态：** 待签；对应返回码 `501`；解禁归属轮次 R3。
