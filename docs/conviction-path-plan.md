# 定罪路径计划（执行契约）

本契约补充现役 v2 对明确路径定义的执行能力，不替代法学会签。当前 `core_rules.json` 未提供该定义，不能把既有 `charge_candidate`、界分方向、说明文字或未命中规则推断成排除路径。正式 §9.4 语料路径映射仍待法学负责人；显式请求罪名覆盖接口由本次补丁加入。

## 规则定义

在 `conviction` 或 `distinction` 规则的 `outcome.candidate_paths` 中声明路径。规则登记仍从 pending 开始，引用已登记法源，通过正常 signoff 后才可能执行；法源本身也必须有 signed_off 状态及对应批准记录。规则、模板和法源的首次插入不得直接写入评审完成状态。

每条路径包含：

| 字段 | 含义 |
|---|---|
| path_id、label、charge_key | 路径标识、展示名称及已审定罪名键；不由执行体生成 |
| actor_fact_key | 已核实且有冻结证据的事实键，其 actorId 必须唯一指向同一快照中的参与人 |
| supporting_fact_keys、contrary_fact_keys | 法学定义的支持/相反事实键，执行体验证事实及证据闭包并输出规范证据身份 |
| when_true、when_false | 父规则实际求值为真/假时明确采用的分支，不从真假自行推定法律排除 |
| subjective | 可选布尔值；明确属于主观认识路径且存在相反证据时输出 conflicted，并阻断 |

分支对象只包含 `baseline_position`（candidate、alternative_to_examine、excluded）及可选 `exclusion_reason`。排除分支必须有明确非空理由与相反事实键；候选分支须有支持事实。规则包不得使用未知字段或重复路径标识；每个执行时点至少有两个明确路径，不能用另一个时点补足当前时点。

## 冻结输入与结果

执行体不从证据类型推定支持/相反关系；角色只来自明确计划。事实必须 confirmed，并明确关联同一不可变快照内、规范身份可唯一解析的 confirmed 证据。各支持/相反事实如包含 actorId，必须与路径参与人一致。UUID 按规范形式解析；其他外部别名区分大小写，歧义别名拒绝。

输出 `candidate_paths` 包含参与人、罪名键、双方证据数组、法源与规则版本、时点、基准位置和排除理由。主执行及行为/裁判时点分别执行，并保留独立身份；同一文档可支持一个事实并反驳另一个事实，两侧分别去重，不删掉一侧。

任何输入、证据、择法或整体模块阻断时，保留路径与双方证据诊断，但 `baseline_position`、`exclusion_reason` 清空，路径携带具体 blockers。conflicted 不得 calculated。所有 calculated 路径仍是 candidate、须人工复核；页面不显示为已确认排除。

旧规则缺少计划时保留规则诊断，返回空路径，页面显示尚未提供路径计划。这是兼容旧注册数据的明确缺口，不构成 INV-CONV-001/002/004 已全部满足；正式语料的多路径映射仍待审定资料；请求罪名接口仅精确匹配已会签的明确 coverage，不补出缺失的法律映射。

## 验收范围

纯执行与实际页面测试覆盖规范证明身份、参与人隔离、真假分支、排除理由、相反证据冲突、非法输入和双时点独立性。隔离 CI 规则使用 2200/2201 年测试区间，与既有 2026 夹具分离；这些规则及 `ci-fixture-reviewer` 的签署只用于技术验收，不是正式法学批准。真实 HTTP 用例验证核实路径可复核批准、候选证明或冲突路径不能批准、历史载荷不变。

Engine V7 前向迁移补首次插入评审门闩，并提供有会签记录及法源闭包的有效只读视图；V6 原不可变/更新/删除守卫与历史行保留。带数据 V6→V7 升级回归验证旧绕过签署的数据保留在历史但不再出现在有效视图中。

## 显式请求罪名与覆盖

定罪派发可带可选请求体：`{"requestedCharges":[{"requestedCharge":"用户原始名称","chargeKey":"调用方明确提供的标识"}]}`。最多32项，每个名称/标识最多200个Unicode字符；标识可缺失或为null。请求原值冻结进metadata、派发输入哈希和重试；名称不自动转换为标识。空数组明确不限定请求罪名，旧省略请求体仍兼容。其他模块不接受非空罪名请求。

执行体在as-of及每个明确已知行为/裁判日期，使用同批有效已会签规则的 `coverage.covers` 精确匹配；缺失日期不推定。覆盖记录保留该时点的规则ID/版本/hash与法源身份，覆盖规则即使谓词false也保留法源版本依赖并进行解析。未覆盖的请求返回 `missing_item: charge_out_of_coverage` 和原始请求名称、明确标识与时点，整体blocked。规则计划自身的罪名不在覆盖内时，不进入candidate_paths；它没有用户原始名称，缺失项的requested_charge为null，不伪造用户请求。

页面名称和可选标识分开编辑。重新分析保留当前冻结请求；明确清空提交空数组；切换案件清空旧案件编辑状态。缺口独立展示，不转换成近似罪名或候选路径。上述技术机制不证明任何新增罪名已获得法学批准。
